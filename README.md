# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Webpack

Структура проекта:

- src/ — исходные файлы проекта
- src/components/ — папка с JS компонентами
- src/components/base/ — папка с базовым кодом

Важные файлы:

- src/pages/index.html — HTML-файл главной страницы
- src/types/index.ts — файл с типами
- src/index.ts — точка входа приложения
- src/scss/styles.scss — корневой файл стилей
- src/utils/constants.ts — файл с константами
- src/utils/utils.ts — файл с утилитами

## Архитектура проекта

Проект реализован на основе архитектуры MVP с использованием EventEmitter-а.

Основные слои:

- Model (модель данных, включая API, классы данных и их коллекции)
- View (слой представления/отображения, отвечающий за визуализацию элементов разметки)
- Presenter + EventEmitter (презентер, валидатор и брокер событий)

### Описание слоев

#### Структура слоя модели (основные классы):

- ProductItem: хранит данные одной единицы товара;
- CustomerProfile: хранит данные покупателя;
- Order: хранит данные оформленного заказа;
- ProductList: основной каталог товаров, который формируется из загруженных с сервера данных;
- BasketList: массив товаров, добавленных покупателем в корзину;
- Api взаимодействия с сервером. Обеспечивает загрузку с сервера каталога товаров, одного определенного товара по известному id, отправку на сервер сформированного заказа. Использует внутренние методы для создания запросов, обработки ошибок и валидации ответов сервера перед взаимодействием с классами данных основной модели.

Приняты следующие решения:

- Создан расширенный класс CustomerProfile. Не все поля класса используются и скорее заложены на будущее;
- Создан отдельный класс Order, отвечающий за сформированный заказ. На текущем уровне реализации проекта наличие класса Order не является обязательным, но может пригодится в дальнейшем. Например, при создании списка заказов;
- Классы-коллекции ProductList и BasketList разделены специально. ProductList является родителем для BasketList;
- Ответы сервера на API запросы могут быть выделены в отдельные классы модели Api, что позволит изолировать проверку ошибок и первичную валидацию.

#### Структура слоя представления (основные классы и компоненты):

- PageView: отображение главной страницы сайта. На главной странице расположена галерея товаров и кнопка корзины с интерактивным счетчиком. Нажатие на кнопку корзины открывает соответствующее модальное окно. Нажатие на карточку товара в галерее открывает модальное окно с превью товара;
- CardBaseView: "основа" карточки, абстрактный класс, который определяет общие поля и методы трёх классов-потомков (CardCatalogView, CardPreviewView, CardBasketView). Позволяет реализовать общий интерфейс и обойтись без дублирования кода представлений карточек;
- PopupView: универсальное модальное окно. Необходимо заполнить отображаемым HTML элементом. Например, элементом превью карточки товара, корзины, форм и т.д.;
- BasketView: представление корзины. Контейнер, содержищий список HTML элементов, представляющих товары в корзине (включая номер товара по порядку и кнопку удаления из корзины). Кнопка оформления заказа, которая неактивна при отсутствии товаров в корзине. Поле, отображающее общую стоимость;
- PaymentFormView: форма выбора способа оплаты и адреса доставки. Данные пользователя передаются для валидации в Presenter. Валидатор в ответ передает форме текст ошибки и переключает состояние сабмиттера;
- ContactsFormView: форма ввода контактных данных. Контактные данные пользователя передаются для валидации в Presenter. Валидатор в ответ передает форме текст ошибки и переключает состояние сабмиттера. При сабмите этой формы генерируется событие окончательного формирования заказа, Presenter формирует соответствующий объект класса Order и передает его в Api;
- SuccessView: представление, которое выводится покупателю при успешном получении сервером заказа. Ответ сервера обрабатывается в Api, извлеченная сумма заказа эмитируется для отображения.

Приняты следующие решения:

- Для классов-представлений продукта определен общий родительский абстрактный класс и общий интерфейс;
- Для классов, которые участвуют в построении списков, реализованы соответствующие интерфейсы-конструкторы. Это позволяет удобно передавать их внутрь других классов и создавать экземпляры уже по месту;
- Реализовано использование универсального модального окна, предназначенного для наполнения различным содержимым. Для окна реализованы базовые методы открытия и закрытия;
- Логику работы с формами можно реализовать разными способами. Автор планирует выполнить последовательную обработку на базе используемого брокера событий.

PS: дополнительно, в ходе реализации проекта нужно будет выполнять проверку HTML элементов при передаче. Для самих же компонентов может понадобится создание "родительских" оберток, реализующих общие методы.

#### Слой презентера

Между вариантом классического строгого презентера и брокера событий был выбран второй вариант.
Использование EventEmitter-а (брокера событий) обеспечивает гибкую и удобную настройку "привычного" событийно-ориентированного взаимодействия между классами разных слоев, позволяет избежать передачи и хранения обработчиков в классах, уменьшает кол-во кода и улучшает читаемость.
Сам же презентер, имея связь как с классами модели, так и с классами представления, содержит в себе обработчики эмитируемых событий, валидаторы и прочее, определяет логику взамидействия слоев между собой.
PS: для интерфейсов и классов, которые используют функционал EventEmitter-а, на текущей версии проекта в определении (extends IEvents / extends EventEmitter) это ещё не показано.

### Примеры классов и их интерфейсов

#### Модель

```
// Единица товара (интерфейс)
interface IProductItem {
    id: string;             // Id товара
    description: string;    // Описание товара
    image: string;          // Ссылка на изображение товара
    title: string;          // Название товара
    category: string;       // Категория
    price: number | null;   // Цена единицы товара (или "бесценно")
}
```

```
// Каталог товаров (интерфейс)
interface IProductList {
    productList: IProductItem[];                    // Каталог товаров
    totalProducts: number;                          // Кол-во товаров в каталоге
    setProductItems(items: IProductItem[]): void;   // Метод, который заполняет каталог
    getProductItems(): IProductItem[];              // Метод для получения полного каталога
}
```

```
// Корзина товаров (интерфейс)
interface IBasketList extends IProductList {
	addProductItem(item: IProductItem): IProductItem;   // Добавить товар в корзину (можно по id)
	removeProductItem(id: string): void;                // Удалить товар из корзины
	calcTotalPrice(): number;                           // Рассчитать стоимость товаров в корзине (метод модели)
	clearBusket(): void;                                // Очистить корзину
}
```

#### Представление

```
// Интерфейс представления карточки (для абстрактного класса и трёх его потомков)

	id: string;

// Универсальный конструктор для карточек

// Абстрактный класс карточки, в котором определены общие поля и методы
abstract class CardBaseView implements ICardView {
    id: string;
    render(item: IProductItem): HTMLElement;

// Один из классов-представлений для карточки товара
```

### Брокер событий. Неокончательный перечень эмитентов, событий и слушателей

События, эмитируемые моделью:

| Эмитент     | Название                   | Данные                    | Описание                                                                                                                           |
| ----------- | -------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| ProductList | "productList:changed"      | нет                       | сообщает в презентер об изменении каталога продуктов                                                                               |
| BasketList  | "basketList:changed"       | кол-во товаров, стоимость | сообщает в презентер о факте изменения корзины + кол-во товаров + стоимость                                                        |
| Api         | "api:productList_received" | каталог товаров           | передает полученный от сервера каталог в модель                                                                                    |
| Api         | "api:productItem_received" | товар                     | передает данные отдельного товара в модель                                                                                         |
| Api         | "api:order_success"        | данные заказа             | в случае успешной обработки сервером заказа, необходимо будет отобразить соответствующий попап, удалить закаказ и очистить корзину |

События, эмитируемые представлением:

| Эмитент          | Название               | Данные                   | Описание                                                              |
| ---------------- | ---------------------- | ------------------------ | --------------------------------------------------------------------- |
| PopupView        | "popup:opened"         | нет                      | сообщает в презентер, что открыто модальное окно                      |
| PopupView        | "popup:closed"         | нет                      | сообщает в презентер, что модальное окно закрыто                      |
| PageView         | "basket:selected"      | нет                      | выбор корзины на главной странице для отображения корзины             |
| CardCatalogView  | "cardCatalog:selected" | id: string               | выбор товара из каталога на главной странице для отображения превью   |
| CardPreviewView  | "cardPreview:toggle"   | id: string               | добавить(удалить) товар в корзину                                     |
| CardBasketView   | "cardBasket:delete"    | id: string               | удалить товар из корзины                                              |
| BasketView       | "basket:checkout"      | нет                      | начать оформление заказа в корзине                                    |
| PaymentFormView  | "paymentType:changed"  | paymentType: PaymentType | сообщает об изменении способа оплаты                                  |
| PaymentFormView  | "address:changed       | address: string          | сообщает об изменении адреса доставки (сначала идет в валидатор)      |
| PaymentFormView  | "paymentForm:submit"   | paymentType, address     | сабмит формы                                                          |
| ContactsFormView | "email:changed"        | email: string            | сообщает об изменении email-а (сначала идет в валидатор)              |
| ContactsFormView | "phone:changed"        | phone: string            | сообщает об изменении телефонного номера (сначала идет в валидатор)   |
| ContactsFormView | "contactsForm:submit"  | email, phone             | сабмит формы                                                          |
| SuccessView      | "success"              | нет                      | успешное оформление заказа (инициирует очистку корзины, заказа и пр.) |

События, эмитируемые презентером

| Эмитент   | Название       | Данные            | Описание                                              |
| --------- | -------------- | ----------------- | ----------------------------------------------------- |
| Presenter | "basket:total" | count, totalPrice | есть ли в корзине товары и сколько они суммарно стоят |

События, эмитируемые валидаторами

| Эмитент   | Название             | Данные        | Описание                                                                  |
| --------- | -------------------- | ------------- | ------------------------------------------------------------------------- |
| Presenter | "paymentForm:valid"  | error: string | сообщает форме об ошибках валидации (или их отсутствии), разрешает submit |
| Presenter | "contactsForm:valid" | error: string | сообщает форме об ошибках валидации (или их отсутствии), разрешает submit |
